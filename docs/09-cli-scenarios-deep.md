# Stratum CLI 深化设计 · 第二部分：32 场景再发散

> 对 `docs/07-cli-design.md` 的 32 个场景逐个再发散：
> **边界分支 / 失败模式 / 场景交互 / 回收的新设计约束**。
>
> 每条都标注它**改变了什么**（新参数、新裁决、或对前文的修正）。
> 这是"设计即标准"的第二遍：第一遍定命令，第二遍定**例外**。

---

## S01 黑匣子长期常开

**边界分支**
1. **`--retain 24h` 到底有没有生效，怎么验证？** → 需要 `stratum session info --retention-status`，
   输出"最老数据 = 3h12m 前 / 淘汰点 = 24h"，否则用户只能等一天才知道配置对不对。
2. **保留检查是异步的**（`--retention-check-interval 1s`）→ 磁盘可能**瞬时超过** `--retain-bytes`。
   → **新约束**：`--retain-bytes` 是"目标值"而非"硬上限"，文档必须说清；需要 `--retain-bytes-hard` 才是硬约束。
3. **重启后保留窗口从哪个时间算？**
   → **裁决**：基于**数据时间**（最新一条的 ts − retain），而非 `created_at_ns`。
   若按会话创建时间算，重启会产生一个新会话，窗口会"重置"，导致旧数据永远删不掉。

**失败模式**
4. 淘汰速度跟不上写入速度 → 磁盘持续增长。→ **新约束**：`status` 必须输出**淘汰速率**，
   并与写入速率对比；若淘汰持续落后 → 告警（这正是 `DP-02`"容量自管理"的实质）。

**场景交互**：与 S27（多实例）叠加时，多个实例各自持有 `--retain-bytes` 会让总和翻倍。
→ **新约束**：`--retain-bytes` 需支持 `--retain-bytes-scope {instance,dir,fs}`。

---

## S02 容量自管理

**边界分支**
1. **删除速度跟不上写入** → 需要降级：先 `drop-newest`，仍不缓解则 `stop`。
   → **新约束**：`--on-disk-full` 支持**链式策略**：`drop-oldest,then-stop`。
2. **容器/配额下 `statvfs` 报的是宿主容量。** → **新约束**：`--assume-capacity 20GB`
   允许显式覆盖，并在 `status` 中标注"容量为假设值"。
3. **LSM 删除是逻辑删除（tombstone），空间不立即释放。**
   → **这是重要洞察**：用户看到"我删了 10GB 但磁盘没变"会以为工具坏了。
   → **新约束**：`prune` 后必须提示"空间将在 compaction 后释放，可用 `--vacuum` 立即回收"。

**失败模式**
4. `--min-free` 触发但**磁盘已 100% 满**，连日志都写不进去。
   → **新约束**：预留一个极小的 `--emergency-log` 通道（固定大小环形，优先写入）。

## S03 触发式录制

**边界分支**
1. **pre-buffer 在内存，崩溃就丢。** → **裁决**：`--pre-buffer-storage {memory,disk}`，
   默认 `memory`（快），但 `--pre-buffer > 60s` 时**强制提示**内存占用。
2. **触发判定用哪个时间戳？** → **裁决**：**接收时间戳**（本地判定）。
   源时间戳可能因时钟异常不可靠，用它会漏触发或误触发。
3. **post-buffer 期间再次触发** → **裁决**：**延长当前会话**（不新建），
   并在元数据中记录触发次数（否则事后看是一段连续数据，不知道触发了 5 次）。

**失败模式**
4. **永不触发** → pre-buffer 一直占内存且无产物。→ **新约束**：`--max-wait`（默认无限制，
   但 `status` 必须显示"已等待 X 小时，触发条件未满足"）。

---

## S04 按日程录制

**边界分支**
1. **窗口边界正在录制** → **裁决**：**在窗口结束时刻切分**（`--window-cut {hard,soft}`，
   默认 `hard`：到点就切，即使正在写）。
2. **DST（夏令时）**：春季跳过的那个小时，cron 表达式**不会触发**。
   → **新约束**：`config explain` 必须打印"在 TZ=Asia/Shanghai 下，
   该日程未来 30 天将触发 N 次，跳过 M 次（DST）"。
3. **`--window-keep` 与 `--retain` 冲突** → **裁决**：**取更严者**（更早触发淘汰）。

**失败模式**
4. **进程在窗口期间不在（崩溃/重启）** → **裁决**：**不补录**，但在元数据记录"错过窗口"，
   使 `verify` 能把"设备没开"与"数据丢了"区分开。

---

## S05 只录指定话题

**边界分支**
1. **同一话题运行时改名**（SEDP 重新公告）→ **裁决**：按**名字**归类，
   新名字 = 新话题；旧名字在改名时刻终止（记录为 `renamed`）。
2. **`--on-missing-topic wait` 期间的数据** → **不录**（话题尚未出现），
   但**必须记录"等待了 X 秒"**，否则事后看到"开头少了一段"会误判。

**失败模式**
3. **通配符匹配到回放时自己发布的话题**（与 S09 交互）→ `--ignore-self` 不够，
   因为它只按本地 participant 过滤。
   → **新约束**：`--exclude-self-topics`（记录本进程发布过的话题名，录制时排除）。

**场景交互**：与 S11（影子流量）叠加时，影子话题名可能与 `--include` 匹配。
→ **新约束**：`--include` 默认**排除**带 `.shadow` 后缀的话题名（可关）。

---

## S06 不干扰业务

**边界分支**
1. **预算超限时丢数据** → `RC-1`，**必须进质量报告**（已设计）。
2. **`--budget-cpu 0.5` 在 8 核机器上是什么含义？**
   → **裁决**：**单核的 50%**（不是总 CPU 的 50%）。措辞改为 `--budget-cpu-cores 0.5` 更清楚。
3. **与 `--durability strict` 冲突**：strict 需要每条 `fsync`，IO 预算必然超。
   → **新约束**：校验时若二者同时出现 → **警告并要求 `--yes`**。

**失败模式**
4. **无 cgroup（旧内核/容器）时无法测量** → 降级为 `warn` 并**在 `status` 中标注"预算未生效"**
   （不能假装在管）。

---

## S07 变速回放

**边界分支**
1. **1000 倍速下时间戳间隔被压到 0** → **新约束**：间隔有**下溢保护**
   （最小间隔 `--min-send-interval`，默认 1µs），并在报告中说明"已达到发送上限"。
2. **`--rate` 与 `--max-rate` 冲突** → **裁决**：取**更慢者**，并提示哪个生效。
3. **接收端处理不过来** → 发送侧不知道，会持续丢。
   → **裁决**：**不做自适应限速**（不可预测），但 `--wait-for-ack` 可让发送侧感知；
   报告必须给出"对端确认率"。

**失败模式**
4. **变速后源时间戳是否重写** → **不重写**（保持"当时"），
   但下游按时间戳排序时会看到"比实时快"。→ **新约束**：`play` 结束必须打印
   "源时间戳范围 X~Y，实际耗时 Z 秒，等效速率 N 倍"。

---

## S08 回放控制

**边界分支**
1. **`seek` 后已发布的数据无法撤回** → 必须**显式说明**：
   `seek` 只影响将来，下游已经收到的数据仍在。
2. **`pause` 期间 DDS 匹配可能因超时断开** → **新约束**：`--keepalive`（默认 on）
   在暂停期间继续发心跳，避免对端认为发布者消失。
3. **控制 socket 权限** → 0600 + 同用户校验；跨用户需显式 `--allow-other-user`。

**失败模式**
4. **多个控制客户端同时操作** → **裁决**：**后到者生效**，并广播一条
   `{"event":"preempted","by":"..."}` 给先前的客户端，避免用户以为自己的命令没生效。

---

## S09 回放话题冲突

**边界分支**
1. **`--require-idle` 是瞬时检查，存在竞态**（检查后原发布者启动）。
   → **裁决**：措辞为"尽力而为"；提供 `--require-idle-window 2s`（观察窗口）降低概率，
   但**不承诺**绝对安全。诚实优于假保证。
2. **`--on-topic-conflict suffix` 的后缀规则** → **裁决**：`<name>_replay`；
   若已占用则 `_replay2`、`_replay3`…（上限 100，超出报错）。
3. **同一会话内两个话题映射到同一目标** → **必须报错(2)**。

**失败模式**
4. **映射目标与记录中其他话题重名** → **报错(2)**，并列出冲突项。

---

## S10 循环回放

**边界分支**
1. **`--loop-until` 落在轮次中间** → **裁决**：**跑完当前轮再停**
   （避免半轮数据让下游看到不完整的周期）。
2. **`--loop-gap` 期间时间轴空档** → 下游可能误判为数据丢失。
   → **新约束**：`--loop-gap-mode {silence,heartbeat,marker}`，默认 `heartbeat`。
3. **无限循环 + 日志增长** → 日志轮转（默认 10MB × 5）。

**失败模式**
4. **`--rewrite-ts` + `--order source_ts` 同时给** → 重写会改变顺序语义
   → **必须警告**，并要求 `--force` 才执行。

---

## S11 影子流量

**边界分支（含对前文的修正）**
1. **上一稿我写"标记应加在负载里"—— 这个判断需要修正。**
   加在负载里会**破坏负载格式的兼容性**（下游按 IDL 解析会失败）。
   → **修正后的裁决**：**不侵入负载**。标记通过三处表达：
   * 话题名后缀（`--tag-shadow-suffix .shadow`）
   * 样本的 `instance_key` 或新增的元数据字段
   * 发送侧在 SEDP 公告的 `participant_name` 带上 `[shadow]`
   并在文档中**明确说明局限**：无法在负载内区分。
2. **影子数据的时间戳** → **保持原值**（否则无法与真实数据对比时序）。

**失败模式**
3. **影子流量挤占真实流量带宽** → **新约束**：`--tag-shadow` 隐含
   `--max-rate` 为真实录制速率的 1×（可覆盖），避免影子把链路打满。

---

## S12 故障注入

**边界分支**
1. **可复现性**：随机数基于**样本全局序号 + seed**（不是时间），
   否则同一 seed 两次运行结果不同。
2. **`drop` 与 `--wait-for-ack` 交互** → 丢包会触发重传，注入效果被抵消。
   → **新约束**：`--inject-seed` 与 `--wait-for-ack` 同时给时**警告**。

**失败模式**
3. **注入配置必须写进会话元数据**（`play` 的产物或审计日志），
   否则事后无法判断"这次异常是真实的还是我们注入的"—— 这会毁掉 `SC-08` 的全部价值。

---

## S13 时间范围读取

**边界分支**
1. **`--stream` 与 `--format table` 冲突**（table 需要对齐 → 必须缓冲全部）
   → **裁决**：`--stream` 时**强制** `jsonl`（或 `csv`），并提示原因。
2. **`--limit` 与 `--stream`** → **裁决**：`limit` 先于 stream 生效（限制总数），
   不是"限制缓冲"。
3. **导出期间会话被删** → **新约束**：导出自动获取**读锁**；若会话被删则失败(8)并说明。

**失败模式**
4. **极大结果无进度** → 进度写 stderr（默认 5s 一次），`--quiet` 关闭。

---

## S14 定点状态重建

**边界分支**
1. **`--state-at` 早于会话开始** → `out_of_range`（已设计）。
2. **keyed 话题**：每个 instance 各有状态 → **新约束**：无 `--instance` 时，
   输出**所有 instance 的状态数组**，而不是随便挑一个。
3. **`dispose` 之后又出现** → 返回**最新状态**，并提供 `--explain` 给出变更序列
   （`appear → update×N → dispose → appear`），因为"现在是什么"与"经历过什么"是两回事。

**失败模式**
4. **同一时间戳多条**（`EC-03`）→ 取 `seq_in_ts` 最大者，并在输出中标注
   `"tie_broken_by":"seq_in_ts"`（不隐藏这个事实）。

---

## S15 完整性报告

**边界分支**
1. **`RC-2` 发现延迟无法从数据判断** → **只能给估计**。
   → **诚实裁决**：报告写"开头可能有最多 X 秒未录（估计值，依据首次 SEDP 时间）"，
   并明确标注**这是估计**。
2. **报告要能对比两个会话** → `verify --compare a b`（`SC-05` 需要）。

**失败模式**
3. **HTML 必须自包含**（无 CDN 依赖），因为审计场景常在离线环境查看。
4. **`--exit-code-on-issue` 需要阈值** → **新约束**：`--max-gap-percent 0.1%`
   （否则"有一条缺口就退出码 4"会让 CI 永远红灯）。

---

## S16 多会话对齐

**边界分支**
1. **时钟偏差估计需要重叠数据** → 无重叠时**报告"无法估计"**，不猜。
2. **不同会话的 `topic_id` 不同**（各自分配）→ 必须**按名字**对齐。
3. **对齐后是否改写时间戳** → **不改**，只加 `clock_offset_estimate` 标注。

**失败模式**
4. **合并产物的格式** → 保持原格式，元数据加 `merged_from: [a,b,c]`，
   使"这是合成的"这一事实永久可见。

---

## S17 性能基线与规划

**边界分支**
1. **`--threshold 10%` 相对还是绝对？** → **两者都支持**：
   `--threshold-rel 10%` / `--threshold-abs 5ms`。
2. **基线会过期** → **新约束**：`--baseline-max-age 30d`，超龄则**警告**而非直接失败。

**失败模式**
3. **`plan` 的外推** → 明确标注"**仅线性外推，未考虑季节性**"；
   给区间而非点估计。宁可给一个丑但诚实的区间。
4. **`diff` 的可比性**：不同配置/不同话题集的会话不可比 → **必须警告**并列出差异项。

---

## S18 `prune`（按条件删除）

**边界分支**
1. **删除后会话其余部分仍可回放** —— 应保证。
2. **删除必须与索引原子化**：先写 tombstone 与 manifest，再改索引，
   中途崩溃可回滚。→ **新约束**：`prune` 是事务性的，`--dry-run` 输出必须包含
   "崩溃安全性：可回滚"这一行。
3. **删除会在时间轴留下空洞** —— 这是**主动**造成的。
   → **关键裁决**：`verify` **不得**把它报告为"缺口"或"数据丢失"，
   而应报告为 `pruned`（人为裁剪）。**否则 `SC-12` 审计场景会得出错误结论。**
   → **新约束**：`prune` 必须在元数据中记录裁剪区间，供 `verify` 区分。

**失败模式**
4. **quarantine 区无限增长** → `--quarantine-ttl 30d`（默认），到期自动清理并记录。

---

## S19 会话批量清理

**边界分支**
1. **`--keep-tagged` 与 `--older-than` 的优先级** → **tag 优先**（显式保护胜过隐式规则）。
2. **正在被其他进程读取的会话** → 检测打开的文件描述符（`/proc/*/fd`）或读锁；
   被占用则**跳过并报告**，不阻塞整个批处理。

**失败模式**
3. **试图删除当前正在录制的会话** → **拒绝(7)**，并提示"请先 `ctl shutdown`"。

---

## S20 归档与冷存

**边界分支**
1. **归档后本地是否保留** → `--keep-local`（默认 on）/ `--move`。
2. **原子性**：先写 `<name>.partial` 再 rename，避免"看起来归档完了其实是半截"。
3. **远端不可用** → 重试 + 断点续传（记录已传偏移）。

**失败模式**
4. **导入时格式版本高于本地** → 拒绝(2)并说明（`FR-S-2`）。

---

## S21 `ctl stop` / `pause` / `add`

**边界分支**
1. **`stop` 后又 `add` 同名话题** → **裁决**：**续用原 `topic_id`**
   （保持时间轴连续，便于按话题查询），但记录一条 `control_event`，
   使"中间断过"与"一直在录"可区分。
2. **`pause --all` 期间心跳** → **继续**（否则对端认为录制器消失，重新发现会有额外延迟）。
3. **`stop` 时缓冲区里还有该话题的数据** → **裁决**：**写完再停**
   （丢掉已接收的数据违背 `FR-R-6` 的诚实原则）。

**失败模式**
4. **`--reason` 超长** → 截断到 512 字符并标记 `truncated: true`（不静默截断）。

---

## S22 快照

**边界分支**
1. **快照与 `prune` 的引用计数** → 快照存在时，其覆盖的底层数据**不可删除**；
   `prune` 必须检查并报告"有 N 个快照依赖该区间"。
2. **快照在 `session list` 中如何呈现** → 作为**独立会话**列出，并标注
   `snapshot_of: <parent>`、`is_snapshot: true`。
3. **对快照再快照** → 允许，但限制深度（默认 8）避免滥用。

**失败模式**
4. **快照后主录制继续 → 数据分叉**：两者**共享历史**，新数据只进主会话。
   → **必须文档化**，否则用户会以为快照是"冻结的完整副本"而期待它也有新数据。

---

## S23 状态与指标

**边界分支**
1. **指标基数爆炸**（每话题一个 series） → 默认只导出**汇总 + Top-N 话题**，
   全量需 `--metrics-all-topics`。
2. **`--listen` 安全** → 默认 `127.0.0.1:9100`；暴露到外网需 `--listen 0.0.0.0:9100 --i-know`
   （避免无意中把内部指标暴露）。

**失败模式**
3. **录制崩溃后 `status` 怎么办** → 返回**上次已知状态** + `"stale": true` + 最后心跳时间。
   不能返回"未知"（那样监控就瞎了）。

---

## S24 动态调参

**边界分支**
1. **`set` 是否持久化到配置文件** → **不持久化**（只影响当前会话）。
   否则重启后行为与用户以为的配置不一致。→ **新约束**：`ctl set` 的响应中提示
   "此改动仅对当前进程有效；如需永久请修改配置文件"。
2. **对正在进行的窗口立即生效还是下个窗口** → **裁决**：`--apply {now,next-window}`，默认 `now`。

**失败模式**
3. **多参数的原子性** → **全有或全无**（部分生效会让状态难以推理）。
4. **回滚** → `ctl set --revert-last`（保留最近 10 次变更）。

---

## S25 无人值守与恢复

**边界分支**
1. **恢复的判定依据** → 元数据 `closed_at_ns == 0`（未正常关闭）。
2. **截断会丢数据** → 必须**报告丢了什么**（时间范围、条数估计），不能静默跳过。
3. **恢复后是否续用原会话** → **裁决：续用**。否则黑匣子会被切成两段，
   `SC-01` 复盘时要跨会话查，容易漏。

**失败模式**
4. **崩溃循环**（每次启动都崩） → 限制重启次数（默认 5 次/小时），
   超限后写入 `crash-loop` 标记并停止尝试，等待人工介入（否则日志会被刷爆）。

---

## S26 配置校验与生成

**边界分支**
1. **`config explain` 要模拟 30 天** → 输出磁盘增长曲线（含保留淘汰），
   直接回答 `EC-17`（"窗口设错会不会立刻删光"）。
2. **`validate --strict` 对未知字段** → **拒绝**（避免拼写错误被忽略，如
   `retention` 写成 `retain`）。

**失败模式**
3. **`config init` 模板必须带注释**，且注释里说明**每项的后果**
   （不是"retain：保留时长"，而是"retain：超过此时长的数据会被删除；设为 0 表示不删"）。
4. **不支持配置热加载** → **明确文档化**，并指向 `ctl set`。

---

## S27 多实例与并发

**边界分支**
1. **`--instance-id` 唯一性** → 启动时检查同目录已有实例的 id，冲突则拒绝(3)。
2. **共享磁盘配额** → 各实例独立计算，**总和可能超**。→ **新约束**：
   同目录多实例时，`status` 显示**目录级聚合**，让用户看到总和。
3. **`--allow-multi-writer` 下的数据交织** → 各写自己的地层文件，
   查询时按 manifest 合并。→ **新约束**：manifest 必须记录 writer 身份，
   否则无法判断"这段数据是谁写的"。

**失败模式**
4. **socket 名冲突** → 已按 instance-id 命名；若用户显式指定同名 socket → 拒绝(3)。

---

## S28 跨机回放与容器

**边界分支**
1. **`advertised_address` 自动检测的局限**：多网卡时会选错。
   → **新约束**：检测到**多网卡**时（>1 个非 loopback 地址），
   启动时**打印所有候选并要求显式指定**（或 `--advertised-address auto` 承担风险）。
   这是本项目踩过的坑：不设会回退到探测地址，NAT 下对端不可达，
   症状是"发现成功、SEDP 正常、Writer 已匹配但收不到数据"。
2. **bundle 传输中会话被修改** → 传输前后校验和比对。

**失败模式**
3. **容器中 UID/GID** → `--uid`（已设计）；若无法降权则**警告**（不要静默以 root 运行）。
4. **跨版本导入** → 格式版本检查 + 明确错误信息。

---

## S29 时钟异常

**边界分支（含重要新约束）**
1. **`clamp` 会改写时间戳 → 数据不再反映真实！**
   → **关键新约束**：`clamp` 时必须同时保留**原始时间戳**（新增字段
   `raw_source_timestamp_ns`），否则我们就永久丢失了"当时到底是什么时候"这一事实 ——
   而保留事实正是这个项目的存在意义。
2. **`reject` 的粒度** → `--on-clock-reject {drop-sample, stop-recording}`，默认 `drop-sample`。
3. **多发布者偏差（`EC-02`）** → 需要**按发布者**统计偏差（不是全局一个数）。

**失败模式**
4. **时钟跳变与倒退必须分开计**（实现中已有 `clock_jumps` 与 `timestamp_regressions`），
   CLI 报告同样分开呈现。

---

## S30 磁盘写满

**边界分支**
1. **`stop` 后锁是否释放、会话是否正常关闭** → **必须正常关闭**（写元数据、释放锁），
   使这个会话**可用**（而不是留下一个"受损会话"）。
2. **`warn-and-continue` 会持续失败刷日志** → 限流告警（同类消息 60s 一次）。

**失败模式**
3. **`--min-free` 与文件系统预留（ext4 默认 5%）叠加** → 文档必须说明：
   当 `--min-free` 小于预留空间时，实际可用会**更早**耗尽。
4. **磁盘恢复后是否自动继续** → `--resume-on-free`（默认 on），
   并记录"因磁盘满暂停 X 分钟"到元数据（避免事后误判成数据丢失）。

---

## S31 误删 / 误改

**边界分支**
1. **`--repair-index` 可能引入错误** → 默认 dry-run + **先备份原索引**（`.idx.bak`）。
2. **校验和粒度** → **每地层文件一个**（默认，快）；`--checksum-block` 提供块级（慢，定位更细）。

**失败模式**
3. **部分损坏的可恢复性** → **能读多少读多少**，报告中给出
   "可恢复 X 条 / 损坏 Y 条 / 未知 Z 条"三分，不允许只报"损坏"一个数。
4. **与归档的关系** → 支持从归档恢复被损坏的地层。

---

## S32 发现延迟与录制器自身

**边界分支**
1. **`--ignore-self` 的判定依据** → **按 participant guidPrefix**，不是按名字。
   （名字可改；guidPrefix 是身份。用名字会在改名后失效。）
2. **发现延迟窗口无法精确知道** → 只能给估计（基于首次收到 SEDP 的时刻），
   并标注为估计值（与 S15 一致）。

**失败模式**
3. **话题抖动（`EC-05`）** → `--on-topic-flap {ignore,new-session,warn}`，
   默认 `ignore`（保持同一会话，记录抖动事件）。
4. **录制器被自己发现（`EC-10`）** → 除 `--ignore-self` 外，
   还应在 `verify` 报告中提示"检测到录制器自身参与者的痕迹"，便于排查配置错误。

## 汇总：本次发散回收的 18 条新约束

| # | 新约束 | 来源场景 | 性质 |
|---|---|---|---|
| 1 | `--retain-bytes` 是目标值；硬上限需 `--retain-bytes-hard` | S01 | 新参数 |
| 2 | 保留窗口按**数据时间**续算，不按会话创建时间 | S01 | 裁决 |
| 3 | `--retain-bytes-scope {instance,dir,fs}` | S01×S27 | 新参数 |
| 4 | `--on-disk-full` 支持链式策略 `drop-oldest,then-stop` | S02 | 语义扩展 |
| 5 | `--assume-capacity`（容器/配额下 `statvfs` 不可信） | S02 | 新参数 |
| 6 | **LSM 删除是逻辑删除，空间延后释放** → 必须提示 | S02 | 文档+提示 |
| 7 | `--pre-buffer-storage {memory,disk}` | S03 | 新参数 |
| 8 | `--max-wait`（触发式永不触发时可见） | S03 | 新参数 |
| 9 | `window-cut {hard,soft}`；DST 跳过要预告 | S04 | 裁决 |
| 10 | `--exclude-self-topics`（与回放/影子交互） | S05×S09×S11 | 新参数 |
| 11 | `--budget-cpu-cores`（明确是单核比例） | S06 | 措辞修正 |
| 12 | **`--inject` 配置必须写入元数据** | S12 | 强制 |
| 13 | `--stream` 时强制 `jsonl`；导出加读锁 | S13 | 裁决 |
| 14 | **`prune` 造成的空洞必须标为 `pruned`，不是缺口** | S18 | **关键裁决** |
| 15 | `--apply {now,next-window}`；`ctl set` 不持久化 | S24 | 裁决 |
| 16 | **`clamp` 必须保留 `raw_source_timestamp_ns`** | S29 | **关键裁决** |
| 17 | 多网卡时必须要求显式 `--advertised-address` | S28 | 新行为 |
| 18 | 恢复时续用原会话 + 报告丢了什么 | S25 | 裁决 |

### 其中三条最值得强调

1. **#14 `prune` 的空洞不是缺口** —— 否则审计场景会把"我们自己删的"当成"数据丢了"，
   与 `ctl stop` 留痕是同一个道理：**主动行为必须与被动缺失区分**。
2. **#16 `clamp` 必须保留原始时间戳** —— 我们为了保住 LSM 不变量而改写了时间戳，
   但**不能因此丢掉"当时到底是什么时候"这一事实**。保留事实是本项目的存在意义。
3. **#13/#4/#19(隐性) "宁可丑但诚实"** —— 多处裁决选择了"报告不确定性"
   而不是"给一个看起来干净的结论"（如 `RC-2` 只能给估计、`plan` 只给区间、
   `diff` 不可比要警告）。
