## 快速结论（"能稳定完成什么"）

**单机、单域、按录制速率**的前提下：

* **双向互通**：回放条数对账 **200/200**；录制方向 `序号缺口: 0`；
* **大 payload**（≤ 60000 B）全部完整；
* **多话题并发**：零串扰；**keyed 话题**：4 个实例 4 种 key 正确提取；
* **QoS 判定**：矩阵 6/6（含两个"正确拒绝"）；
* **实时延迟**（录制方向）：**P50 0.136 ms / P99 0.363 ms**；
* **速率控制精确**：抖动与期望逐一吻合；
* **长时稳定**：soak 55 轮 RSS/FD 恒定（无泄漏）；
* 全量 `ctest` **33/33**。

**可靠性边界（实测）**：丢包 ≤ **1%** 时可靠传输**完全收敛**；**≥5% 会残留**未补齐样本
（5% → 94.5%、10% → 92.5%，成因未定位）。见 `scenarios/20_packet_loss.sh`。

**不能承诺**：**跨主机部署**（未实测 —— `netns`/`veth`/`tc` 在本环境全部不可用，
需第二台主机）、**高速/突发回放**（根因在接收端内核缓冲）、
**单条 > 64 KiB 样本**（未实现 `DATA_FRAG`，仅显式失败）、**IPv6**（双栈整体缺失，已决策不做）。

详见 [`02-open-issues.md`](02-open-issues.md)。

## 环境要求（复现前必读）

```bash
# 运行任何诊断工具/脚本都需要：
export LD_LIBRARY_PATH=/UserData/Fast-DDS/build-fastdds/src/cpp:/opt/ros/jazzy/lib:/UserData/Fast-DDS/_deps/sysroot/usr/lib/x86_64-linux-gnu
```

上游 Fast DDS 位于 `/UserData/Fast-DDS`（**只读**，Release 构建 —— 因此
`Log::SetVerbosity(Info)` 拿不到 EDP 的 Info 分支，取证要用行为证据而非日志）。

**排查纪律**（本项目用血换来的）：
1. **不要凭推断说"上游拒绝了什么"** —— 拿返回值/抓包/字节 dump；
2. **静默失败优先怀疑**：本项目 6 处静默失败，每一处都表现为"看起来正常、实际没通"；
3. **"共用标识 / 重复实现"优先怀疑**：4 处，每处都是"修了一个副本、另一个没修"；
4. **声明必须与实际一致**：3 处，每处都是"本端以为兼容、对端认为不兼容"；
5. **先测量再优化**：两轮凭直觉的"限流"都白做，`/proc/net/snmp` 一眼定位；
6. **失败也要写下来**：否则下一个 agent 会重复同样的弯路；
7. **新写的测试脚本自己也会错**（本会话踩过两次）：
   * 一次是随机套件把 `topic2` 算进期望值 —— 而差额**恰好等于** `topic2`，
     那正是"多话题隔离生效"的证据，却被误读成大面积丢数据；
   * 一次是边界脚本把"空时间线的非零返回码"当崩溃、把"补救副本"当多余数据、
     忘了开 `STRATUM_DUMP` 导致判据恒为 0。
   **结论**：脚本 FAIL 时**先怀疑判据**，再怀疑被测对象；数值异常时先看
   "它是否恰好等于某个已知量"。
