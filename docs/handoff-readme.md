## 本项目的三个核心判断

这三点贯穿全部文档，是本项目与其他录制工具的根本差异：

### 判断 1：DDS 只有"现在"，没有"过去"

DDS 的历史缓存是为**传输**服务的（重传、补发给晚加入者），不是为**存储**服务的。
默认每个实例只保留 1 条，且随进程生命周期消失。

**Stratum 补的就是这一层。**

### 判断 2：数据可信度是产品的一等公民，不是附加功能

黑匣子类产品的价值完全建立在"数据可信"之上。
如果用户不能确定录制是否完整，**复盘结论就不可信**。

而最危险的不是"知道数据不全"，是**"以为录全了，实际漏了"**。

见 `06-data-trust.md`。

### 判断 3：真正让系统在现场失效的，是运维问题而非功能缺失

磁盘满、崩溃后没恢复、配置漂移、SIGTERM 没处理——
这些不是功能不完整，是**长期运行的健壮性问题**。

见 `07-deployment.md` 第 9 节。

## 术语表（核心）

完整术语表见各文档，这里列出最容易混淆的几个：

| 术语 | 定义 |
|---|---|
| **Session（会话）** | 一次录制的完整产物，是回放/查询/管理的基本单位 |
| **Layer（地层）** | 一个分片文件。⚠️ 术语待确认（与 LSM 的 level 区分） |
| **源时间戳** | 数据的**发布者**打的时间。回放默认用它保证时序保真 |
| **接收时间戳** | **录制器**收到数据的本地时刻。用于诊断录制延迟 |
| **环形保留** | 只保留最近 N 时间/空间的数据，旧的自动淘汰 |
| **快照** | 录制进行中，把"目前为止"固化为可独立使用的 Session |
| **QoS 还原** | 回放时使用录制时记录的 QoS，而非默认值 |
| **质量报告** | 回答"这份录制可不可信"的诊断输出 |
